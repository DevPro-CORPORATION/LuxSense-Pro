Frequently Asked Questions (FAQ)

Clear answers to questions regarding updates, telemetry security, calibration, and licenses.

Q1: How does the Automatic Update System distinguish stable releases from prereleases?

LuxSense Pro inspects the prerelease Boolean flag in the GitHub Releases REST API payload. By default, only releases where prerelease == false and draft == false are considered. If a user wishes to participate in preview releases, they can enable "Include preview and pre-release builds" in the Settings tab.

Q2: Can LuxSense Pro ever downgrade automatically?

No. The update manager parses installed and remote versions into semantic version objects using Python's packaging.version.Version. An update prompt is only triggered if published_version > installed_version. If a remote release has a lower or equal version number, the application safely declares that it is up to date.

Q3: Are GitHub write-access tokens embedded anywhere in the code?

No. LuxSense Pro never embeds API tokens. The application utilizes GitHub's public, unauthenticated Releases REST API endpoint. CI/CD release publishing runs strictly within GitHub Actions runners utilizing temporary GitHub workflow tokens.

Q4: How do I export my historical sensor measurements?

Navigate to the Analytics & History tab in the desktop application. Click Export CSV to save all historical readings with exact timestamps, packet IDs, raw lux, and calibrated lux.

Q5: Where can I submit a bug report or feature request?

You can use our official GitHub Issue templates: Submit Bug Report or Request Feature.
